## 5. C：最小人工搜索责任状态合同

### 5.1 可复用身份

- `mission_epoch`：直接复用为跨 START/STOP 的硬栅栏。
- `authority_revision`：每次 authority modes 真正变化时递增，可与 `mission_epoch + vehicle_id` 共同形成 planner-owned `control_segment_id`；无需再建全局 ID 服务。
- 声明 `event_id`：仅用于同一声明幂等；相同 ID/相同负载 no-op，相同 ID/冲突负载 fail-closed。
- 现有 Recorder 自生 segment ID 不能回流作为生产权威；应改为记录 planner 发布的 ID。

### 5.2 最小状态记录

不新建第二套状态机；在当前 planner authority owner 中只保存一个可选记录：

`human_search = {vehicle_id, mission_epoch, control_segment_id, event_id, declared_sim_ns, active}`

| 输入事件 | 前置条件 | SEARCH 责任结果 | 规划行为 |
|---|---|---|---|
| mission START / 新 epoch | 合法全局 START | 清空为 NONE | 正常初始规划 |
| TAKEOVER 或切艇 | authority 接受 | 清除旧艇；新艇仍为 NONE | 不因接管加入 fixed center |
| 显式 SEARCH 点击 | 当前人工艇；epoch/segment 匹配；任务 SEARCHING | 设 ACTIVE | B2=当前位；B3=有效预测，否则当前位；再触发一次可审计 replan |
| 重复同一 event_id | payload 完全相同 | 不变 | no-op，不重复 replan/revision |
| NAVIGATE | 合法目的地命令 | 在执行目的地前撤销 ACTIVE | NAVIGATE 不作为搜索 fixed center |
| CANCEL / RELEASE / 控制段结束 / 切艇 | 合法 lifecycle/authority 事件 | 清空 | 移除固定人工中心并重规划 |
| STOP / terminal | 当前 epoch | 清空并封闭 | 不接受迟到声明或预测 |
| observation event | 合法独立观测 | 不变 | Bayesian 链按自身合同处理 |

### 5.3 迟到预测与重规划

- `CANDIDATE`：预测必须匹配当前 mission epoch、vehicle、control segment，且采样时刻不早于段起点；否则拒绝。
- B3 只在 ACTIVE SEARCH 中消费预测；无效/缺失预测走 `b3_center_policy()` 的当前位置 fallback，不阻断整队规划。
- 预测时域、有效性窗口和触发重规划的中心位移阈值仍是 `OPEN QUESTION`，本任务不选择数值。

## 6. D：有效目标遭遇 evaluator 最小合同

### 6.1 与现有实现的差异

- `target_search_node.py` 当前 engineering GT 指标只检查“任意艇瞬时距离小于 ground_truth_range”，没有逐艇连续 dwell、离开重置或 tau。
- 该逻辑与 Search/Bayesian owner 同节点，且现有正式 FOUND 仍由 calibrated `Gamma` 合同定义；不能直接改名为 RC 的阶段成功。
- 随机 POSITIVE 观测不能作为 encounter success，waypoint/SEARCH/NAVIGATE 也不能直接产生 success。

### 6.2 最小 evaluator I/O（`CANDIDATE`）

输入：

- evaluator-only target pose；
- 10 艘艇的有效 fleet pose 与仿真时间戳；
- run_id、mission_epoch、全局 mission state；
- 经负责人批准的 `R`、`tau`、budget。

内部状态：每艇独立 `outside | inside_since_sim_ns`。进入半径时开始；离开立即只清该艇；禁止跨艇累计。新 epoch/START 清全部；STOP/terminal 封闭。缺失/无效 pose abstain；仿真时钟回退应 fail-closed/INVALID，而不是继续累计。

输出：truth-free 的 encounter 结果，仅含 run_id、epoch、vehicle_id、entry/completion sim time、dwell duration、结果/原因；不得含目标坐标。Recorder 可记录；planner、posterior、coverage、B2/B3 不得读取 GT 或距离。

### 6.3 终止与删失

- 首次单艇完成连续 tau 的仿真时刻是 `T_encounter`，NAVIGATE 与自主航行同等评价。
- 到预算仍无 encounter：BUDGET_EXPIRED，正常右删失。
- 人工 STOP、INVALID、进程崩溃、时钟回退是异常/管理终止，不得标为正常右删失成功。
- `OPEN QUESTION`：当前正式 FOUND 专属于 calibrated Gamma；需要批准 encounter 使用独立终态/结果字段，或批准其如何映射任务终止。不得由本地实现暗改 FOUND。
- `OPEN QUESTION`：encounter 完成与 budget deadline 同一仿真 tick 的优先级。
