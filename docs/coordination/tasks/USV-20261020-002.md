## 4. 本任务工程预算的确定边界

- `t_start` 为合法 START 的同域仿真时刻；`deadline=t_start+budget`。重复 START 不刷新起点；同一合法新 epoch 重置。
- wall clock/外部 timeout 只能用于运行安全，不能生成科学 budget terminal。
- 预算未到不提前结束；达到 deadline 且无更早合法权威终态时，仅终止一次 `BUDGET_EXPIRED`。
- 截止时间及之后采集的事件不得成为预算内新 evidence；终止后到达的事件不得更改该 epoch 的 posterior。截止前采集、截止后送达的事件需要明确审计，不应回填或静默改写终态。
- pending-positive 不得无限挂起预算，但不能在本任务将 POSITIVE 升级为成功或新的 FOUND。
- 后续行政 STOP 和 Recorder teardown 不能将 `BUDGET_EXPIRED` 覆盖为 STOPPED。
- 自然终止必须停止 Planner/MUX 路径执行并使十艇 20 路实际 thruster topic 归零。
- 对工程完成的 budget-limited no-confirmation run，可记录预算达到与未确认事实；**在 RC-20261020-v1 的 encounter evaluator 尚未实现前，不得把该记录写成“无有效遭遇的正式右删失”**。如旧 004D 用 `budget_right_censored` 命名，必须审查并限定统计端点/证据等级；严禁以 `T_conf=null` 推出 `T_encounter` 不存在。
- `R`、`tau`、正式实验 budget、encounter/FOUND 映射、同 tick encounter vs budget 优先级以及 B3 预测数值仍交研究总控；不自行填写。
