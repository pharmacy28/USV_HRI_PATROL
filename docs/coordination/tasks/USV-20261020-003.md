## 1. 唯一目标和本轮边界

**只实现并验收单艇人工显式 SEARCH 声明 → planner-owned 搜索责任 ACTIVE → B2 人工当前位置 fixed center → 合法撤销、幂等及 Recorder 审计。**

`TAKEOVER` 仅表示控制权，**不自动成立人工搜索责任**；`NAVIGATE` 有目的地但也**不成立 SEARCH 责任**。不要求 SEARCH 预先指定坐标/区域。自主艇仍在可搜索自由空间作责任分区，既有 A* 路径成本→Hungarian 顺序不变。

本轮只对 **B2=human_current** 的当前位责任闭环给生产验收。对于 B3，只保证不存在 SEARCH 声明时不能注入人工 fixed center；**B3 预测无效回退到当前位置的生产接入留给后续 004**，不得把本任务声称为 B3 完成。

002 的 `BUDGET_EXPIRED` hard terminal、Recorder 删失字段与安全屏障不得回归。RC 的有效目标遭遇（R 连续 tau）及正式预算/确认均**不属于本任务**。

## 3. 先核对入口，最小化协议

001 已确认全局 `/planning/set_search_enabled` 与单艇人工 SEARCH 是不同含义。不要以全局 START 或接管代替 SEARCH。

优先复用现有 operator→planner ingress。当前 NAVIGATE schema 若强制目的地、无法无歧义承载无目的地 SEARCH，可在**现有 package 内**增加一个极小的 `/operator/search_declaration` topic（推荐 schema `search_declaration/v1`）；无需新增 ROS node/package/service/事件总线。

至少包含：
- 事件唯一 `event_id`；
- `mission_epoch`；
- `vehicle_id`；
- **planner-owned** `control_segment_id`（可由 epoch、vehicle、authority_revision 等已有可靠变化量派生，先验证跨接管/切艇唯一性）；
- 行为 `SEARCH_ACTIVE` / `SEARCH_CANCEL`；
- 仿真事件时刻 `simulation_timestamp_ns`。

不得用 Recorder 自行生成的 `vehicle:segment_NNN` 作为 planner 接受命令的权威。若缺少稳定控制段身份，先局部补足 planner-side 语义，不创建第二套全局状态机或 ID 服务。

**操作 UI 的物理键位/点击映射若当前未冻结，不自行选快捷键或篡改现有导航按键。** 实现可由 operator 端明确发送的规范 ROS 声明入口，真实联调可经规范 ROS 消息触发；若尚未验证实际 UI 点击发出该声明，将 `OPERATOR_UI_CLICK` 标记 NOT_OBSERVED，而不能把 CLI 发布说成用户点击已验收。

## 4. 生产权威状态与变迁

在当前 planner/authority owner 内维护**唯一可选**人工搜索责任记录（而非独立状态机）：

`human_search = {vehicle_id, mission_epoch, control_segment_id, event_id, declared_sim_ns, active}`。

必须落实：

1. 新 mission START/epoch：责任为 NONE；STOP、BUDGET_EXPIRED、FOUND、INVALID 等 terminal 清除并关闭新声明。
2. TAKEOVER：维持原控制权安全合同；可按既有权限机制重规划，但**不插入人工搜索 fixed center**。切艇时取消旧责任，新艇不自动继承。
3. 声明 SEARCH_ACTIVE：仅当前真实 HUMAN_CONTROLLED 车辆、当前有效 epoch/segment、合法 ACTIVE mission 可接受；无需目的地。成功声明后激活当前艇人工搜索责任，并按既有机制触发**一次可审计的语义重规划请求**。
4. 相同 event_id+相同归一化 payload：DUPLICATE/no-op，不重复责任变迁/重规划；同 ID 不同 payload：CONFLICT/fail-closed。
5. SEARCH_CANCEL、NAVIGATE、现有语义取消/替换、RELEASE、CONTROL_SEGMENT_END、切艇、STOP/terminal：按当前权威生命周期撤销旧 SEARCH 责任；需要时触发一次有意义的重规划，但不得把撤销本身当作 target observation。
6. 错 epoch、错 vehicle、旧 segment、迟到/无效 stamp、旧控制权 revision、terminal 后消息：REJECTED，不复活旧责任；若 stamp 校验涉及未冻结数值窗口，不得自造 TTL，只校验已有可证明的因果/epoch/segment 顺序。
7. 所有命令结果可以在既有 planner/authority status 与 Recorder 中按 event_id、segment_id 关联；Recorder 是**下游记录者**，不能成为生产搜索责任 owner。
8. 同一时刻最多一个有效人工 SEARCH 责任；其他人工控制艇即使存在，也不得因接管被自动设为 fixed center。

本轮不用增设独立消息持久化或重启恢复；无法恢复旧 epoch/段权威状态时 fail-closed。

## 5. 固定中心生成与 B2

在现有 `human_current`、`human_predictive` 等模式的 fixed-center 入口增加 **SEARCH ACTIVE gate**：

- 未 ACTIVE：人工接管和 NAVIGATE 目的地都不产生**人工搜索责任 fixed center**，同时人工控制艇继续按既有 authority 规则从自主 Hungarian pool 中剔除；不得因取消 fixed center 又把人控艇悄悄放回自主分配池。
- 已 ACTIVE 且模式为 B2/human_current：使用**当前可验证的受控艇位姿**作为搜索责任固定中心；不要使用旧 NAVIGATE destination，不把启动时位置永久缓存；如位姿无效要 fail-closed 而不虚构当前位置。
- 责任撤销后该人工固定中心消失，自主中心/责任分区重新按现有算法处理。
- 保持固定中心的 weighted K-means、全自由格 A-lite geometry responsibility partition、A* 路径成本→Hungarian、不改变任何 `b0/bt/S/R_miss`。
- 任何 predicted/oracle center **不得绕开 SEARCH gate**；当前 B3 prediction unavailable 可能报错，这是 004 将解决的既知缺口，本任务不得宣称 B3 fallback 通过。

避免把覆盖 batch generation 当成 SEARCH 声明重规划；Recorder 应有可识别的声明接受/撤销事件及由此请求的 generation 因果链。

## 6. 离线先行验证

先补定向失败测试（当前 takeover/目的地被错误视为 fixed center），再作最小修改。至少包括：

- 全局 START 未人工接管时不创建人工 SEARCH 责任；TAKEOVER 后也没有；
- B2 SEARCH_ACTIVE 后，唯一人工 fixed center 位于当前受控艇位置而非 NAVIGATE destination；
- NAVIGATE 可正常执行，但即使有目的地也不成为 SEARCH 中心，且撤销原 ACTIVE；
- CANCEL/RELEASE/切艇/段终止/新 epoch/STOP/BUDGET_EXPIRED 均清理责任；
- 新艇要重新声明，旧 event/revision/segment/epoch 被拒绝；
- 同 ID 同内容幂等、冲突 fail-closed；声明被拒绝不能偷偷重规划；
- 控制权剔除自主池与 fixed-center gate 相互独立；
- Search/NAVIGATE/预测/控制输入不直接修改 posterior；合法观测在没有人工 SEARCH 时仍会更新；
- K-means 责任中心固定、全部自由格几何分区、A* cost→Hungarian、A-lite/MUX/STOP/004D 预算终止回归不退化；
- 既有 B3 RF 不可用问题明确留待 004，不为让本轮测试通过而隐式改变预测算法/阈值。
