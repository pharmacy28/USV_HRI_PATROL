### 核心时间证据（必须真实采集）

为同一 run_id/epoch 形成单一时间线：

- `/clock` 仿真时间序列，至少覆盖 START、TAKEOVER、SEARCH_ACTIVE、CANCEL/NAVIGATE/RELEASE、terminal；
- `ros2 param get` 或实际 node parameter 对 Planner `use_sim_time=True` 的实证；
- Planner 的 authority、SEARCH declaration/result、control_segment、generation 等实际 `simulation_timestamp_ns`，含每项事件 ID；
- 上游 command acquisition stamp 与 planner acceptance stamp 的因果关系；
- Recorder 对应事件时间与原始消息时间对照；
- B2 fixed-center 实际座标，与相应仿真时间的 `/overview/fleet_state` 对照；
- ROS Search 的 mission epoch/terminal 与 Recorder 不混时域。

检查所有 `simulation_timestamp_ns` 在同一仿真 run 的合理 `/clock` 时间区间内且单调/因果相容（按相同对象的真实时序），**不得出现 Unix epoch 量级的 wall ns**。如存在消息接收/处理延迟，应保留真实差异而非强制 stamp 相等。不能只用 `use_sim_time=True` 参数、launch SHA 或 Recorder 单侧数值证明修复；需跨节点真实 event/record 对照。

若声明消息由 ROS CLI/脚本触发，明确记为 API 级测试；`OPERATOR_UI_CLICK=NOT_OBSERVED`，不将其升级为 UI 验收。
